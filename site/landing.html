How it works

  1. 1

    A two-minute interview

    The assistant asks what you run, what to ignore, how often and when, and where to send the report. Every question has a default, so "defaults" is a valid answer. It can also read your stack from a repository or an SBOM.

  2. 2

    A schedule in your assistant

    It creates a scheduled task where your assistant supports one. Where it does not, it sets up GitHub Actions or cron. It keeps a small state file so nothing is sent twice, and sends you a test digest right away.

  3. 3

    A digest you can act on

    Each run checks the sources, matches them to your stack, puts exploited issues on top and says what to do. Reply "hide WordPress" or "I patched nginx" and the next reports follow it.

Built to be trusted

Runs in your assistant

There is no service and no account. This site is static. Your stack, your schedule and your state stay where your assistant keeps them.

Reports, never changes

The instructions forbid the assistant to patch or reconfigure anything. It tells you what to do, you decide.

Facts with sources

Every CVE, version and "exploited" status comes from a source and links to it. Unknown stays "unknown".

Feeds are data

Advisories are written by other people. The assistant is told never to follow instructions found in them.

A script you can read

vuln_feed.py fetches and deduplicates. Python standard library only, about 500 lines, tested offline.

Says when it breaks

A source that did not answer is named in the digest. A lost state is rebuilt from the last date, not resent.

Questions

Which assistants does it work with?

Any assistant that can read a web page and keep a schedule. If yours has scheduled tasks (Claude, ChatGPT, Gemini and others offer them in some plans), the digest runs there. If it does not, the assistant sets up a GitHub Actions workflow or a cron job instead. The instructions tell it to check its own platform's current features rather than guess.

Do I need to write code?

No. You answer questions in plain words. The assistant writes the profile, the schedule and, if needed, the workflow.

What does it cost?

The instructions and the sources are free. Each run uses your assistant's usage like any other task. The default sources need no API keys.

Will I get the same vulnerability every day?

No. The assistant remembers what was delivered. An item comes back only with something new: it was added to CISA KEV, a public exploit appeared, a fix came out. Then you see just that update, marked 🔄.

Can it read my stack from my code?

Yes. Point it at a repository or an SBOM. It reads lock files, Dockerfiles, Terraform and Helm charts, shows you the list, and you confirm it. Exact package versions go to OSV for exact matches.

What language is the digest in?

Yours. The instructions are in English for the assistant, the digest is written in the language you choose. CVE ids, product names and commands stay as they are.

Is there a Claude Code plugin?

Yes, with the same instructions inside. Run /plugin marketplace add SecH0us3/vuln-digest, then /plugin install vuln-digest@vuln-digest, and ask Claude for a vulnerability digest. The plugin holds one skill and the helper script. It has no hooks and no MCP servers, so nothing runs until you ask.

How do I get new sources and fixes?

If your assistant can keep files, your digest runs from a copy saved at setup, so a change on this site never changes it behind your back. Once a week it checks for a new version and adds one line to the digest if there is one. Say "update vuln-digest", and the assistant shows what changed (new sources, new commands, what leaves your machine) and replaces the copy only if you agree.

How do I change or stop it?

Tell the assistant: "send it at 9", "only Mondays", "less about PHP", "stop". It changes the profile or the schedule and confirms the next run.
