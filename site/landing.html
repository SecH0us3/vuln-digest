How it works

From your repositories to your inbox, in four steps

  1. I

    It looks before it asks

    If your assistant is connected to GitHub, GitLab, Confluence or Notion, it reads your lock files, Dockerfiles, Helm charts, Terraform and infrastructure pages. Read only: it does not clone, run or change anything, and keeps no code or secrets. No connector? Give it a repository, an SBOM, or just a list.

  2. II

    It asks only what it could not find

    "nginx and PHP 8.3 are in three repositories - is that production?" "Ruby is only in a two-year-old service - ignore it?" Then when to send, where, and in which language. Every question has a default.

  3. III

    It schedules itself

    A scheduled task in your assistant, or GitHub Actions or cron where there is none. A small state file makes sure nothing is sent twice. You get a test brief right away.

  4. IV

    You read, act and steer

    Exploited issues in your stack come first, with fixed versions and a command to check. Reply "hide WordPress" or "I patched nginx" and the next briefs follow. Once a month it can look at your repositories again and ask about anything new.

Why read it

What you get

Five minutes instead of a morning of feeds

One short brief instead of advisories, mailing lists and vendor blogs. On days with nothing new, one line.

Only what you run

Matched by meaning: ingress-nginx is nginx, GKE is Google Cloud. What you never want to see stays out.

Exploited first

CISA KEV, public exploits and EPSS decide the order. An exploited issue in your stack can come as an urgent alert, not tomorrow.

A next step, not just a CVE

The fixed version, whether yours is affected and a command to check it, taken from the source and linked.

Your stack stays with you

No service, no account. The profile and the state live where your assistant keeps them. Only public feeds are read.

No lock-in

Free and MIT licensed. Plain instructions any assistant can follow: switch assistants and take your setup with you.

The interview

What it asks you

  • Which connectors it may read your stack from: GitHub, GitLab, a wiki
  • Whether what it found is in production, and anything it missed
  • What never to show: vendors, products, bug classes
  • How much to show from outside your stack
  • How often, what time, your time zone
  • A weekly summary: yes or no, which day
  • A line on quiet days, or silence
  • Urgent alerts for exploited issues in your stack
  • Where to send it: chat, email, Slack, Telegram, Teams, a file, a GitHub issue
  • Language and length
  • Which sources, and what is exposed to the internet

Ground rules

Built to be trusted

Runs in your assistant

There is no service and no account. This site is static. Your stack, your schedule and your state stay where your assistant keeps them.

Reports, never changes

The instructions forbid the assistant to patch or reconfigure anything. It tells you what to do, you decide.

Facts with sources

Every CVE, version and "exploited" status comes from a source and links to it. Unknown stays "unknown".

Feeds are data

Advisories are written by other people. The assistant is told never to follow instructions found in them.

A script you can read

vuln_feed.py fetches and deduplicates. Python standard library only, about 700 lines, tested offline.

Says when it breaks

A source that did not answer is named in the digest. A lost state is rebuilt from the last date, not resent.

On file

Questions

Which assistants does it work with?

Any assistant that can read a web page and keep a schedule. If yours has scheduled tasks (Claude, ChatGPT, Gemini and others offer them in some plans), the digest runs there. If it does not, the assistant sets up a GitHub Actions workflow or a cron job instead. The instructions tell it to check its own platform's current features rather than guess.

Do I need to write code?

No. You answer questions in plain words. The assistant writes the profile, the schedule and, if needed, the workflow.

What does it cost?

The instructions and the sources are free. Each run uses your assistant's usage like any other task. The default sources need no API keys.

Will I get the same vulnerability every day?

No. The assistant remembers what was delivered. An item comes back only with something new: it was added to CISA KEV, a public exploit appeared, a fix came out. Then you see just that update, marked 🔄.

Can it read my stack from my code?

Yes, and it tries that first. If your assistant has a connector or MCP server for GitHub, GitLab, Confluence or Notion, it reads your lock files, Dockerfiles, Terraform, Helm charts and infrastructure pages, shows you what it found and where, and you confirm it. Without one, point it at a repository or an SBOM. Exact package versions go to OSV for exact matches.

What language is the digest in?

Yours. The instructions are in English for the assistant, the digest is written in the language you choose. CVE ids, product names and commands stay as they are.

Is there a Claude Code plugin?

Yes, with the same instructions inside. Run /plugin marketplace add SecH0us3/vuln-digest, then /plugin install vuln-digest@vuln-digest, and ask Claude for a vulnerability digest. The plugin holds one skill and the helper script. It has no hooks and no MCP servers, so nothing runs until you ask.

I installed the plugin, why is it missing in the Claude desktop app?

The commands above install it for Claude Code on your computer. In the desktop app it shows up in the Code tab, in a local session: click + next to the prompt box, then Plugins. If a session was already open, type /reload-plugins in it. Chat and Cowork do not read plugins installed from the terminal: they take plugins and skills from your claude.ai account. There, paste the prompt above instead. The setup asks the same questions.

How do I get new sources and fixes?

If your assistant can keep files, your digest runs from a copy saved at setup, so a change on this site never changes it behind your back. Once a week it checks for a new version and adds one line to the digest if there is one. Say "update vuln-digest", and the assistant shows what changed (new sources, new commands, what leaves your machine) and replaces the copy only if you agree.

How do I change or stop it?

Tell the assistant: "send it at 9", "only Mondays", "less about PHP", "stop". It changes the profile or the schedule and confirms the next run.
